# G2 平台边界退出审计

- 审计日期：2026-08-31
- 当前结论：未通过 G2 退出门槛
- 审计范围：全部 `eiscore-*/src`、根部 `shared/`、`@eiscore/platform`、工程契约测试与已接受 ADR

本审计把“已有平台模块”和“业务已完成迁移”分开判断。只有存在全产品范围证据、剩余例外已分类并由门禁锁定时，能力才可标记完成；G4 企业配置包、服务端授权和业务级错误文案不冒充 G2 前端平台完成证据。

## 锁定库存

`tests/engineering/g2-platform-boundary-inventory-regression.mjs` 以精确文件和调用数锁定以下未完成项：

- 原生 Storage：16 个文件、58 处引用。
- `window.location.href =`：20 个文件、24 处；其中认证/登录兼容跳转与跨模块业务跳转必须在迁移时分别评审。
- 权限适配器：9 个，均必须依赖 `@eiscore/platform/permission`，不得重新内联角色和权限数组规则。
- `eis-data-grid-v2`：8 份应用级副本，禁止增加第 9 份。

该门禁是“只降不增”基线，不表示现有库存合理，也不要求把业务内路由、离线数据或领域授权粗暴塞进一个通用工具。

## 退出阻断项与顺序

G2 只有在以下三项完成并有全量证据后才能关闭：

1. 明确的跨模块跳转全部通过平台导航或受控宿主路由，并完成动态跳转复审。
2. 16 个 Storage 消费者按持久化语义迁入安全适配器；存储异常不能破坏页面主流程或泄露值。
3. 8 份 Grid 副本收敛为单一来源，所有应用通过兼容入口消费同一实现。

下一批优先迁移 5 文件/7 处明确跨模块全页跳转；之后处理材料端与移动端两份同构盘点缓存，再评估 Grid 单一来源的机械迁移路径。
