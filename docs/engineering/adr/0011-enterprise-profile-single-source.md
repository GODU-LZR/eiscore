# ADR-0011：企业公开档案以企业站点配置为唯一运行时来源

- 状态：接受
- 日期：2026-09-02

## 背景

现有实现把企业名称、品牌、Logo、主题、联系方式和公开站入口分别保存在部署级 `eiscore-enterprise.json`、`system_configs.app_settings.loginBranding`、`company_site.site_config`，部分企业独立站还把同类字段写死在页面组件中。多个入口可以修改相同事实，但没有一致的发布和同步事务，已经出现客户文案残留、入口指向错误以及运营台修改无法反映到公开站的问题。

## 决策

- `company_site.site_config` 的已发布记录是企业公开档案的唯一运行时事实源。企业法定名称、品牌名称、品牌简称、工厂名称、Logo、公开联系方式、公开域名、站点主题和 SEO 基线均由“企业站点运营”维护、审核和发布。
- `config/eiscore-enterprise.json` 继续作为不可变的部署启动配置，负责企业标识兜底、服务端点、模块开关和功能开关；数据库暂不可用时可以回退到该配置，但它不是运营人员日常修改企业资料的第二入口。
- `system_configs.app_settings` 只保存系统界面偏好，包括内部系统标题覆盖、内部主题覆盖、通知、业务参数和功能展示。历史 `loginBranding` 数据在迁移期保留读取兼容，但企业档案加载成功后不得覆盖已发布企业事实，也不再由系统设置页面编辑。
- `@eiscore/platform/enterprise-profile` 负责把公开站点响应规范化为稳定的 `EnterpriseProfile`，并将它投影到系统外壳和公开站。调用方不得自行拼接企业名称、Logo 或公开站 URL。
- “企业站点运营”是企业公开档案的唯一编辑入口；系统设置展示档案摘要并导航到企业运营，不复制编辑表单。
- 站点标识由运行时依赖注入或部署配置提供，产品代码不得新增客户名称、客户域名或客户 Logo 默认值。

## 兼容与回退

- 没有企业站模块、公开接口不可用或尚未发布档案时，系统继续使用部署级企业配置，现有系统设置仍可加载。
- 迁移期不删除 `app_settings.loginBranding` 和客户 seed；回退只需停止加载运行时企业档案，数据库结构和已发布内容无需删除。
- 独立站和管理端沿用现有 `/agent/company-site/public/*` 与 `/agent/company-site/admin/*` 契约，不要求浏览器直连数据库。

## 后果

企业资料只需要发布一次，系统外壳、登录入口和独立站即可使用同一份事实。系统级视觉偏好仍可独立配置，但不会再改变企业法定信息。旧客户页面中的硬编码需要按后续小步迁移到公开内容 API；在全部页面迁移完成前，契约测试会锁定档案字段不得继续新增重复来源。
