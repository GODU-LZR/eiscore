# ADR 0022：雅御隔离开发、测试与静态发布

- 日期：2026-10-20
- 状态：接受（用户授权雅御独立远端环境）

雅御分支继承惠众修复源码，但历史惠众静态包包含尚未合入该分支的定制宿主页面，不能当作雅御源码的可复现构建结果。既有惠众、伦度服务与数据属于独立企业边界。

使用 `/opt/yayu-eiscore` 下独立的 Compose 项目、数据库、秘密、卷、内部网络和 Web 端口。仅公共 HTTPS 入口共用现有边缘 Nginx；新增雅御主域与二级通配符证书、路由前必须备份并执行配置检查，使用 graceful reload。

Node 20 构建容器仅挂载雅御源码、npm 缓存、雅御运行配置及 releases 目录。根据用户后续适配要求构建宿主、apps、人事、销售和移动五个入口；apps 仅为闪念编辑/预览提供运行时，普通应用中心、物料、采购与销售发货隐藏并限制路由。业务边界由模块开关与 Web 路由共同约束。运行配置不携带企业凭据，业务库从受控结构版本初始化，不复制其他企业业务或演示记录。

构建先校验实际雅御品牌配置并运行既有认证、模块路由、企业配置与销售统计回归，再输出不可复用版本号的候选目录。入口、静态资源、配置身份及清单全部校验通过后写入完成标记。发布只切换 releases 父目录中的 `current` 相对软链接，并验证雅御固定 Web 容器配置与 loopback 实际版本；不重建其他企业容器。运行 Web 挂载 releases 父目录，避免 Docker 固定挂载旧软链接目标。

回退再次发布已有候选，历史目录和 `previous` 目标保留。数据库迁移、运行时镜像更新、AI 提供方配置、公共证书续期与官网设计分别管理；静态发布不隐式执行这些操作。官网采用雅御业务内容与独立生成的资源，不能将惠众官网公开为雅御正式官网。业务助手和闪念使用从版本源码生成的独立 Harness bundle，保留来源及文件散列；两链路使用独立状态、cookie、工具密钥和数据库角色。
