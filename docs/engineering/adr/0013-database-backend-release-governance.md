# ADR-0013：将 PostgreSQL 与 PostgREST 作为后端发布单元治理

- 状态：接受
- 日期：2026-09-03

## 背景

EISCore 的主要业务 API 由 PostgREST 暴露 PostgreSQL 表、视图和函数提供。数据库函数、触发器、RLS 与授权实际承担传统后端中的业务逻辑、访问控制和接口契约，因此只治理前端与 Node Runtime 不能形成完整的工程化闭环。

仓库当前有 107 份历史 SQL。Runtime V2 的 10 个补丁和 company-site 的 1 个新迁移已具备 Manifest、SHA-256、事务、账本、回退声明与 postcheck，其余 97 份历史 SQL 没有可信全局顺序。生产 Compose 仍以 `db_schema_and_data.sql` 初始化空数据卷，PostgREST 和 Agent Runtime 仍以 `postgres` 连接数据库；这些是已接受但必须消除的迁移期债务。

用户于 2026-09-03 决定暂停 G4.1，优先完成数据库后端治理。

## 决策

1. PostgreSQL Schema、表、视图、函数、触发器、索引、扩展、RLS、角色与授权均视为核心后端源代码；PostgREST 暴露的表、视图和 RPC 均视为公开 API 契约。
2. 数据库核心发布制品独立于企业包，必须绑定 Git 提交、PostgreSQL/PostgREST 版本、基线版本、迁移终点、迁移校验和、目录指纹和 postcheck。企业差异只能进入配置、初始化数据和素材，不得包含客户专属 DDL、函数、RLS 或授权。
3. 所有新数据库变化只允许追加不可变迁移。禁止直接修改已发布迁移、在生产环境手工执行未登记 DDL，或继续向历史 SQL 根投放新补丁。
4. 107 份历史 SQL 保留原位并先分类，不按文件名猜测执行顺序。建立经隔离栈验证、去除客户数据和秘密的规范基线；必须证明“空库基线加迁移”和“上一发布升级”最终目录契约一致。
5. 数据库运行身份至少分离为对象所有者、迁移器、PostgREST authenticator、匿名角色、登录角色和 Agent 服务角色。对象所有者不得登录；PostgREST 与 Agent Runtime 不得以 `postgres` 或其他超级用户运行。
6. PostgREST 只允许暴露已审计 Schema。新增或变更 RPC 必须锁定函数签名、参数、返回契约、Owner、执行权限、RLS 行为和 Schema Cache 刷新；破坏性变更使用兼容窗口或新版本接口。
7. `SECURITY DEFINER` 必须显式批准、固定安全 `search_path`、撤销 PUBLIC 执行权限并具有角色/RLS 负向测试；其余函数默认 `SECURITY INVOKER`。宽泛默认授权和匿名写权限必须作为显式审计项。
8. 每次数据库发布依次执行离线校验、目标预检、可验证备份、受控迁移、迁移账本原子写入、postcheck、PostgREST Schema Cache 刷新和真实角色/API 冒烟。不可逆变化以备份恢复为回退，不编造未经演练的反向 SQL。
9. CI 必须同时验证空库重建、上一版本升级、Schema/API 目录指纹一致、匿名/登录/服务角色权限、RLS 越权拒绝和 PostgREST HTTP/RPC 契约。发布环境使用固定镜像版本或摘要，禁止漂移标签作为正式证据。
10. G4.0 成果保持不变，G4.1～G4.4 暂停；数据库治理完成并通过退出审计后，再由用户决定是否恢复 G4。

## 渐进兼容与回退

- `db_schema_and_data.sql`、现有角色和超级用户连接先作为锁定债务保留；只有隔离栈证明新基线、角色和客户端行为兼容后才替换，不直接修改客户环境。
- 初期采用维护窗口和 expand/migrate/contract 顺序。先增加兼容结构，再发布调用方，最后在后续版本删除旧结构。
- 已登记迁移相同 ID/相同校验和可幂等跳过；相同 ID/不同校验和失败关闭。发现目标 Schema Drift 时停止发布，不自动覆盖未知变更。
- 应用可独立回退时优先回退应用；数据库不可逆或数据损坏时恢复已验证备份，并同时恢复兼容的核心发布版本。

## 验收后果

数据库治理不能以“SQL 能执行”作为完成。退出前必须证明非超级用户完整栈可运行、空库与升级路径等价、PostgREST/RLS 真实角色契约通过、发布制品可追溯、Schema Drift 能失败关闭，并在隔离环境完成至少一次破坏后恢复演练。生产与客户环境仍需逐次明确授权。
