# ADR-0006：领域本地存储使用安全适配器

- 状态：接受
- 日期：2026-08-31

## 背景

Auth/Session 已有统一安全存储，但产品仍有离线队列、页面偏好、Grid 布局和助手历史等非会话 Storage。它们的 Key、格式、失败降级和生命周期不同，不能合并为一个无类型全局对象；继续由页面直接访问浏览器 Storage，又会让禁用存储、配额不足或损坏 JSON 中断业务流程。

## 决策

- 浏览器 Storage 只在共享边界解析，并统一经过 `createSafeStorage` 捕获读取、写入和删除异常。
- 领域服务保留自己的 Key、版本、序列化、默认值和清理规则；页面只消费具名领域函数。
- 共享边界不得记录 Key、Value 或解析失败的原文，不把本地缓存冒充数据库或服务端授权。
- 迁移必须先以特征测试锁定兼容行为，再按缓存族逐步替换，库存门禁只能随证据下降。

首个落地是材料端与移动端盘点缓存：两份实现共享同一服务，保留缓存快照、冷库模式和待同步队列协议，并在 Storage 不可用或队列类型损坏时安全降级。

第二个落地是移动端企业助手与仓储助手会话历史：共享 10 个会话、每会话 40 条消息的有界存储协议；企业助手继续通过注入式消息策略只保存文件类型、名称和图片 URL，不持久化原始 File 对象或非图片临时 URL。

第三个落地是 8 个 Grid Core 的列宽与行高布局：全部消费共享安全布局服务；HR 独有的 `id/employee_no` 行键及 `nextTick` 恢复时序通过注入保留，其他应用继续使用通用行键与宏任务恢复。

## 后果

领域代码减少重复实现，浏览器隐私模式与配额异常不再破坏盘点主流程。不同缓存族仍需独立迁移；本决策不提供加密、跨设备同步、TTL 或冲突解决，敏感数据不得因此写入浏览器持久化存储。
