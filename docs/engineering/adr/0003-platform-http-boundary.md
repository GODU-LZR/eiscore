# ADR-0003：前端基础 HTTP 访问收敛到平台契约

- 状态：已接受
- 日期：2026-08-30

## 背景

EISCore 的多个前端分别使用 Axios、原生 `fetch` 和局部 API 工具，自行拼装 `/api`、认证头、超时、401 跳转与错误文案。相同逻辑存在细微差异，企业 API 基址配置尚不能统一生效，错误对象和日志也可能携带查询参数、Token 或服务端响应内容。

工程测试目录已有一套面向远程检查的重试客户端，但它允许调用方直接提供任意基础地址，返回原始响应，并不适合作为浏览器产品代码的安全边界。

## 决策

1. 在 `@eiscore/platform/http-client` 建立不依赖 Vue、Axios 或具体业务模块的产品级 HTTP 契约；在迁移期由 `@eiscore/platform/axios-client` 提供注入式 Axios 兼容层，平台包不直接依赖 Axios、Vue 或 UI 库。
2. API 与 Agent 地址只从已校验的企业配置解析；业务调用提供资源路径，兼容层也接受严格位于已配置服务根下的完整 URL，但仍会还原为资源路径后重新解析。外部 URL、协议相对 URL、反斜杠、片段和路径穿越立即拒绝。
3. 认证信息通过 `getAccessToken` 适配器注入；平台客户端不直接读取 LocalStorage，也不决定页面跳转。
4. 401 只产生不含敏感值的结构化事件，由宿主适配器负责清理会话和导航；查询参数、请求体、Token 与服务端错误内容不得进入平台错误消息。
5. 默认超时为 15 秒，错误统一分类为 `unauthorized`、`forbidden`、`not-found`、`conflict`、`validation`、`rate-limited`、`server`、`network`、`timeout` 等稳定代码。
6. 平台客户端不自动重试。GET 重试和写请求幂等策略必须在明确业务语义后单独启用，避免重复创建或重复下推。
7. 首个迁移链路是桌面系统配置读写与移动登录配置读取；其他 Request/Auth 工具按业务切片迁移，新代码不得继续直接拼装相同基础能力。
8. 现有基座全局 401 兜底暂时保留，待受保护 API 调用充分迁移并具备覆盖证明后再删除。
9. Axios 兼容层保持可调用 config、`response.data` 返回、调用方显式 Header/Profile、原错误对象身份和无自动重试行为；通知与结构化事件只接收脱敏信息，拒绝前清除错误中的认证头、请求体和查询值。
10. 需要显示服务端业务校验文案的模块必须显式注入映射器；平台只接受 200 字以内、无控制字符、URL、查询结构和秘密字段标记的文本，其余回退到安全通用文案。原生客户端只通过不可枚举的 `displayMessage` 返回审查后的文本，平台错误正文保持脱敏。
11. 动态 Profile 解析器只使用平台提供的无查询资源路径上下文，不根据企业域名、租户前缀或重写后的完整 URL 推断业务 Schema。
12. 基座兼容调用使用自动服务模式时只接受显式 `/api`、`/agent` 前缀，并分别映射到企业 `apiBasePath`、`agentBasePath`；未配置的根路径失败关闭。AI 服务 401 是否影响主会话由基座适配器显式决定。

## 结果

实施继续覆盖基座设置页：宿主适配器公开同一缓存 HTTP 客户端，动态应用列表使用 `app_center` Profile，Agent 配置读写复用 `public` 系统配置服务。该页不再直接拼装 Token 或调用 `fetch`，401 由宿主局部清理并跳转 `/login`；全局 401 兜底仍按决策 8 保留。

采购单据关系的可选查重与写入也复用微应用 Request。适配器允许请求以 `silentError` 或 `suppressErrorMessage` 抑制错误通知，但该判定不改变 401 的统一会话清理；业务层继续把表未部署、查重或写入失败视为可选能力并返回 `null`。

根部共享模块通过独立薄适配器复用平台原生客户端，不从任一宿主或微应用反向导入业务实现。显示配置消费返回的 JSON 数据；精确计数消费响应 Header，并继续在不可用时回退既有 RPC。共享适配器拥有与各应用相同的会话清理和登录跳转策略。

基座 SOP 学习记录属于普通受保护 API，直接复用宿主平台客户端。读取或 upsert 失败不改变页面主流程，只把同步状态降级为本地；401 仍先执行宿主会话失效策略。平台客户端自动序列化对象写入体，业务层不再手工注入 Token 或 JSON Content-Type。

基座布局的身份/权限补全同样属于受保护 API。调用方需要用新 Token 查询用户资料时可显式提供 Authorization；平台仍限制企业端点并执行安全错误与 401 策略。多 Schema/字段回退必须逐请求捕获失败后继续，不能因平台客户端把非 2xx 转为异常而缩短原回退链。静态资产清单和预热请求不纳入认证客户端。

AI Copilot 的系统配置调用复用宿主原生客户端而非强制统一成一种 service 返回语义：模板读取失败为空数组，物料分类读取失败仍允许从空配置追加，而保存失败必须继续映射现有用户文案。共享的是端点、认证、超时、401 与脱敏边界，不抹平业务层已经依赖的回退行为。

只读的智能 BI 行动单列表可直接消费平台 JSON 数据；请求失败或数据形状不符时保持空列表，不把平台错误暴露到页面。需要服务端错误正文的工作流写链与动态导入链继续单独设计。

AI 动态数据导入不再把业务目标直接交给 `fetch`：兼容 `/api` 前缀移除后必须通过平台安全路径验证，并由企业端点重建地址。调用方仍可显式提供业务 Profile；401 映射原专用提示，其他写入错误保持通用“导入失败”。批次号查询需区分有状态 HTTP 错误与无状态网络错误，以保留原回退边界。

移动端考勤、盘点、出入库和仓库查询的四份重复请求器已收敛到同一移动平台适配器。资源路径、查询编码、`hr`/`scm` 默认 Profile、`public` 显式覆盖、方法与请求体保持；401 由移动宿主统一清理并跳转 `/mobile/login`。为保留原短业务提示，原生客户端允许显式映射 JSON 错误体，但只附加通过长度、控制字符、URL、查询结构与秘密标记审查的 `displayMessage`；401、原错误消息与结构化事件不包含服务端正文。

正面影响：

- 企业配置中的公网地址和 API 路径能够真正控制产品请求地址。
- 认证、超时和错误脱敏具有可独立测试的稳定入口。
- 业务 service 不再依赖 Axios 拦截器或页面级 `fetch` 细节。
- 后续收敛 Auth、Storage 与权限时已有清晰的注入边界。

需要承担的成本：

- 新旧 HTTP 实现会在迁移期并存。
- Axios 兼容层是过渡边界；待调用方不再依赖 Axios 返回/错误语义后，才可迁入原生平台客户端。
- 宿主与移动端仍需各自提供会话失效策略。
- 平台错误默认不展示服务端原文；确需用户可见的业务校验信息时，必须通过受控错误映射单独设计。

本决策可按单提交回退，不改变 API、数据库或部署拓扑。
