# ADR-0002：生产环境采用显式、失败关闭的配置契约

- 状态：已接受
- 日期：2026-08-30

## 背景

生产 Compose 曾为 PostgreSQL 密码和 PostgREST JWT 密钥提供可直接运行的默认值，并将一个客户域名写入 OpenAPI 代理地址。两个部署脚本还会在缺少环境文件时自动写入弱密码。这使配置遗漏可以悄悄变成不安全的可运行部署，也阻碍同一制品服务不同企业。

## 决策

1. `POSTGRES_PASSWORD`、`PGRST_JWT_SECRET` 和 `EISCORE_PUBLIC_BASE_URL` 是生产部署必填项。
2. 生产 Compose 使用 `${VAR:?message}`；任一必填项缺失时，Compose 在创建容器前失败。
3. `env/.env` 保存真实部署值并由 Git 忽略；`env/.env.example` 只描述契约，其占位符不得通过部署校验。
4. 数据库密码至少 24 个字符，JWT 密钥至少 32 个字符；二者必须独立生成，并使用 Base64URL 字符集。数据库密码限制为 Base64URL 是因为它当前还被嵌入 PostgREST 数据库 URI。
5. 企业公网地址必须是纯 HTTPS origin，不允许客户硬编码、路径、查询、凭据或末尾斜杠。
6. AI、代理和 Cline 凭据保持可选；未配置时只关闭相应能力，不阻断核心系统。
7. 部署脚本在启动任何服务前调用统一校验器。缺少配置时只能复制模板并退出，不得生成或填充弱默认值。
8. Compose 的服务级 env 文件是可选补充，以支持 CI 或平台通过进程环境注入变量；关键变量仍由失败关闭表达式强制。

## 结果

正面影响：

- 配置遗漏无法退化成弱密码部署。
- 客户域名从产品部署模板中移除。
- 本地脚本、CI 和未来部署平台共享同一份可测试契约。
- 环境文件和错误输出不会打印秘密值。

兼容影响：

- 依赖旧默认值的部署在升级前必须显式创建 `env/.env` 并完成密码轮换。
- JWT 密钥轮换会使现有登录会话失效，需要安排重新登录窗口。
- 已有 PostgreSQL 数据卷不会因为修改容器环境变量而自动修改数据库角色密码，必须按迁移手册先在数据库内轮换。

迁移步骤见 `docs/engineering/PRODUCTION_ENV_MIGRATION.md`。
