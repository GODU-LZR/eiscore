# ADR-0005：前端权限判断收敛到平台服务

- 状态：已接受
- 日期：2026-08-31

## 背景

基座和 8 个业务应用分别维护 `permission.js`。九份实现都读取相同用户信息、兼容三种角色字段并赋予 `super_admin` 全权限，但导出集合、读取异常回退和销售/采购模块权限、经理角色特例不同。此前会话迁移只统一了用户信息来源，没有消除权限规则复制。

## 决策

1. 在 `@eiscore/platform/permission` 提供不依赖 Vue、路由、Storage 或 UI 的权限服务，由调用方注入 `getUserInfo`。
2. 服务统一规范化 `permissions` 与 `app_role`/`appRole`/`role`，保留空权限参数返回 `true` 和 `super_admin` 全权限语义。
3. 默认捕获用户读取异常并按空用户失败关闭；基座通过 `catchReadErrors: false` 保留原异常传播行为。
4. 销售与采购通过受校验的 `moduleId`、`managerRole` 配置启用原模块权限与经理特例。`hasAnyPerm`、`hasAllPerm` 保留原集合级推导规则，不改写成可能改变混合集合结果的逐项判断。
5. 各应用继续导出原有函数集合；质量/设备不新增未曾公开的 `hasAnyPerm`/`hasAllPerm`，应用中心与基座也不新增 `hasAllPerm`。
6. 该服务只控制前端可见性和交互提示，不替代数据库 RLS、PostgREST 授权或服务端权限校验。

## 结果

九个权限工具成为薄适配器，角色别名、异常边界及销售/采购特例由平台行为测试统一保护。新增权限规则必须先进入平台契约或显式领域策略，不能继续复制到应用工具中。

本切片不改变用户信息格式、权限字符串、接口、数据库或部署拓扑，可按单提交回退到各应用局部实现。
