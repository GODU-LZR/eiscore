# ADR-0001：采用渐进式现代化而非整体重写

- 状态：已接受
- 日期：2026-08-30

## 背景

EISCore 已经包含可运行的多前端业务模块、PostgREST 数据接口、Node Agent Runtime、桌面采集器、数据库脚本及多层测试。与此同时，巨型文件、公共代码复制、客户硬编码、依赖漂移和分散的基础设施调用提高了变更风险。

整体重写会同时失去既有业务行为、隐含规则和测试资产，并在较长时间内产生两套系统。继续在现有结构上无边界追加功能也会进一步放大维护成本。

## 决策

采用渐进式现代化：

1. 保持现有系统持续可运行。
2. 先用特征测试、契约测试和业务链测试保护旧行为。
3. 建立企业配置、平台 SDK、共享组件和数据库迁移边界。
4. 新功能只进入目标结构；旧功能在被修改时按业务切片迁移。
5. Node Runtime 优先演进为模块化单体，不在当前阶段拆分微服务。
6. 保留现有主要框架，框架替换必须通过新的 ADR 单独论证。
7. 每个中间状态都必须可以构建、测试、部署和回退。

## 结果

正面影响：

- 可以持续交付业务价值，不需要等待一次长期重写完成。
- 迁移范围可控，失败时能够回到上一个稳定状态。
- 既有测试、业务知识和部署资产可以继续使用。
- 多个 Agent 可以围绕边界清晰的小任务并行工作。

需要承担的成本：

- 新旧结构会在一段时间内并存。
- 需要维护兼容适配层，并持续防止新代码回流旧边界。
- 每次抽取前必须补测试，短期开发速度可能降低。

这些成本是有意接受的，用于换取较低的系统性风险和可持续演进能力。
