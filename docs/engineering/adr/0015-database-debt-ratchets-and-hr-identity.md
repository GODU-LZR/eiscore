# ADR-0015：历史 SQL 最终处置、HR 稳定身份与 public Schema 棘轮

## 状态

接受。只适用于独立重构仓库和后续受控数据库制品；不授权连接或修改原仓库、客户环境及生产数据库。G4/G5 继续暂停。

## 背景

DB6 已建立可发布、可恢复的数据库闭环，但仍留下三个结构性问题：96 份非迁移历史 SQL 只有粗分类，没有可验证的最终处置；HR 只有模块/操作权限，无法安全表达本人和部门数据范围；`public` Schema 只有文档规则，新增对象仍可能在代码审查中漏过。

登录用户和员工档案之间不能使用姓名、工号、部门文本或相似字段推断。`role_data_scopes` 已经表达 `self/dept/dept_tree/all`，但缺少稳定身份外键。`public` 的存量对象又被大量 PostgREST 和前端消费者依赖，不适合一次性改名或搬迁。

## 决策

1. `database/legacy-sql-resolution.json` 是 96 份非迁移历史 SQL 的最终处置账本。每份文件固定路径、原始字节 SHA-256、类别和最终处置；默认禁止执行。只有旧角色升级夹具和 Runtime V2 postcheck 能在声明的隔离上下文执行。账本漂移或缺项使数据库治理门禁失败。
2. `hr.user_employee_links` 以外键建立 `public.users.id` 与 `hr.archives.id` 的一对一桥接，并记录建立时间、更新时间和操作者。JWT `username` 或 `sub` 只用于解析稳定 `users.id`；行级判断之后只使用外键与部门 UUID，不使用文本猜测。
3. `hr.can_access_employee(archive_id,module)` 是员工行范围的单一数据库判定：`self` 为无配置时的失败关闭默认；`dept` 使用部门 UUID；`dept_tree` 使用 `public.dept_tree_ids`；`all` 和管理员可访问未绑定员工及临时工。薪资仍额外要求 payroll 专项权限或管理员角色。
4. `database/public-schema-ratchet.json` 以规范基线对象目录作为存量允许集。CI 同时扫描迁移中的显式 `CREATE public.*`，真实数据库契约测试和发布前后检查实际 Catalog；新增对象除非绑定新迁移与已接受 ADR，否则失败。删除或迁出存量对象不会扩大允许集。
5. 首个低风险下降项是删除无产品消费者、向登录用户暴露原始 JWT 文本与数据库角色的 `public.debug_me`。它不保留兼容 facade；对应过期本体表语义一并删除。

## 兼容与回退

- 未建立身份桥接的普通用户对员工行默认不可见；这属于安全收紧。部署前应由授权管理员以可审计方式建立映射。
- HR 管理员和 `all` 范围继续访问全量；考勤临时工只对管理员/`all` 可见。
- 旧 HR 表名、字段、PostgREST Profile 和考勤视图保持；新增桥接表和四个只读判定 RPC 扩展 API。
- `debug_me` 是调试端点，不属于兼容承诺。若存在未登记消费者，发布契约会体现 path 减少，发布前功能验收必须发现它。
- `core-005`、`core-006` 使用发布前备份恢复回退，不伪造会丢失映射审计或重新暴露调试端点的反向 SQL。

## 结果

历史 SQL 从“未治理库存”变为“不进入迁移链但逐文件有最终处置”的只读证据；HR 本人/部门范围具备稳定身份基础；`public` 从人工约定变为静态、真实 Catalog 与发布三层棘轮。三家客户数据迁移、生产 KMS/备份、容量和功能验收不在本决策授权范围内。
