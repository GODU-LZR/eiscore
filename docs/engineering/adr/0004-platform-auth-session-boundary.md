# ADR-0004：认证会话与浏览器存储收敛到平台契约

- 状态：已接受
- 日期：2026-08-30

## 背景

EISCore 现有 10 份前端 Auth 工具重复实现 `auth_token`、`user_info`、JWT 解析、过期判断和会话清理。实现之间已有偏差：桌面端直接解析 Base64 字节，移动端额外执行 UTF-8 解码；部分存储操作未捕获浏览器安全或配额异常；各模块重复承担 8192 字符 Token 上限。

认证信息同时被平台 HTTP、Axios 兼容层、路由守卫和登录页消费。若直接一次性替换全部应用，影响面过大，也会把页面导航策略错误地下沉到共享包。

## 决策

1. 在 `@eiscore/platform/auth-session` 建立不依赖 Vue、路由或具体应用的认证会话契约，固定兼容 Key 为 `auth_token` 与 `user_info`。
2. 继续兼容纯文本 Token 和 `{ "token": "..." }` 两种存量格式。Token 最长为 8192 字符；读取或写入超限值时立即清理两个会话 Key 并失败关闭。
3. JWT payload 使用严格三段式 Base64URL 与 UTF-8 解码。载荷无效、`exp` 缺失或不是有限数字时一律视为过期；该解析只用于客户端体验和过期预判，不替代服务端签名与权限校验。
4. 在 `@eiscore/platform/safe-storage` 隔离浏览器 Storage。读取失败返回 `null`，写入或删除失败返回 `false`，JSON 解析失败使用安全回退；异常、Key 与 Value 均不进入日志或错误消息。
5. 平台会话不决定页面跳转，也不直接发起 HTTP 请求。桌面与移动适配器分别保留 `/login` 和 `/mobile/login`，401 所有权继续由宿主适配器承担。
6. 首个迁移切片只覆盖基座和移动端，保留原有导出名称与 Token 存储格式。其余 8 个微应用在后续机械迁移切片中接入同一契约。

## 结果

正面影响：

- 桌面和移动端对中文 JWT、过期边界、超长 Token 与存储异常具有同一行为。
- Auth 工具不再直接接触 LocalStorage 或独立实现 Base64 解码。
- HTTP 层继续只通过注入读取 Token，平台包之间保持单向、可测试依赖。
- 后续微应用迁移可以复用同一组契约测试并形成小提交。

需要承担的成本：

- 迁移期仍保留其余 8 份微应用 Auth 兼容实现。
- 安全存储采用失败关闭和布尔结果，调用方若需要向用户解释存储被禁用，必须在具体界面增加受控提示。
- 客户端 JWT 解码不提供真实性保证，服务端仍必须完成签名、有效期和权限校验。

本决策不改变接口、数据库或部署拓扑，可按单提交回退到两端原 Auth 工具。

## 实施状态

首批基座与移动端验证完成后，其余 8 个微应用的 Auth 工具已在后续独立切片中完成同构迁移；10 个 Auth 工具现均依赖同一平台会话契约。随后基座全局 401、移动路由守卫和 4 个移动 API 的失效清理也已改为消费 Auth 适配器，并保留原登录路径、重定向参数和宽松 JWT 路由兼容。基座用户 Store 通过显式 `plain` 写入模式保留桌面纯文本 Token，移动端继续使用默认 JSON 格式。基座布局通过安全的原始用户信息文本保留跨窗口事件和同窗口轮询语义，权限读取也已统一。最后一批 AI、设置、首页、数字孪生与微前端状态桥迁移清除了基座已盘点调用；全产品复审后来发现微应用页面、Store、权限、Realtime 和共享 Grid 副本仍有直接消费者，因此会话消费迁移继续进行，不能视为全产品归零。复审后的用户 Store、权限/Realtime、共享 Grid/Geo、模块局部及 Flash 运行时切片已统一消费 Auth 适配器，并在保留权限特例、WebSocket 协议、Store 优先级、Geo 鉴权、多窗口同步、Flash 工具语义及应用差异的前提下把直接调用从 56 个文件、134 处降至应用中心 7 个文件、56 处。
