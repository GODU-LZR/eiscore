# ADR-0010：以复杂度库存渐进拆分巨型 Vue 页面

- 状态：接受
- 日期：2026-09-01

## 背景

全产品 139 个有效 Vue 文件中，52 个达到 800 行，承载 90,948 行，占 Vue 源码的 78.5%；11 个页面超过 2,000 行。它们同时混合展示、交互、协议、领域规则和状态生命周期，导致小改动需要理解和验证整页。一次性重写会扩大功能丢失、样式漂移和企业上线风险。

## 决策

- 以 800 个物理行为架构审查阈值，机器可读基线锁定现有 52 个文件的逐文件上限、总行债务以及 1,200/2,000 行分层数量。
- 禁止新增巨页或扩大既有巨页；基线扩张必须单独 ADR，不作为普通功能提交的便利手段。
- 保留现有页面为组合入口，按“特征测试 → 纯策略/协议/领域服务 → Composable → 视觉组件”的顺序渐进抽离。
- 每个切片只迁移一个具名职责，不混合业务规则、接口、依赖升级或大规模格式化；公开 Props/Emits、路由、请求、状态转换和视觉行为保持。
- 每个拆分切片必须减少逐文件或总债务，并通过专项回归、完整质量门、离线单元套件和所属产品构建。模板/CSS 变化还必须进行渲染与交互核验。
- `.app-drafts` 属于 Flash 运行期产物，不进入产品源码基线；不得新增排除目录规避治理。

## 后果

巨页风险从主观判断变为可持续下降的工程库存，不阻塞日常功能开发，也不允许继续无成本堆积。物理行只负责触发审查，不代替耦合、测试性和业务边界判断；纯粹搬行、拆成无语义碎片或复制实现不视为完成。
