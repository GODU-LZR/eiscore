# ADR-0017：用户生命周期与服务器日期约束

## 状态

接受。仅授权重构仓库源码与隔离测试，不授权当前点击测试数据库迁移、服务替换或远端发布。

## 背景与决策

用户管理展示了“创建、生效、锁定”，但新增用户默认为生效、登录不检查状态、锁定只依赖前端未持久化的 properties；直接调用 users、用户视图和角色绑定接口均能绕过锁定。视图缺少 users 的创建/更新日期，直接更新 users 也不维护更新时间。

1. 新增不可回写历史的 `core-012`。未来新用户默认 `created`，不批量修改既有用户。`created/draft` 未生效不可新登录；`active` 可登录；`locked` 是已生效冻结资料，仍可登录。仅 active 可进入 locked。
2. 表级触发器禁止修改/删除锁定用户、禁止修改其 user_roles。解除锁定必须是独立请求，只允许 locked→active；同次改资料或角色的请求整体回滚。复用现有管理员判定与 `op:hr_user.edit` 权限，不新增权限体系。只有 create 权限不能在新增请求中直接指定 active 绕过生效操作。隔离初始化与发布角色保留已有数据库管理权限。
3. 既有 `disabled` 无法区分历史“锁定”写入和真正停用。因此不自动转换、不允许新登录；授权管理员需核实后显式恢复 active，再通过修正后的前端保存 locked。其他业务表的 draft/disabled 语义不变。
4. `hr` Schema 承载两个触发器函数。public 上只新增三个必须挂在既有 users/user_roles 表上的约束/日期触发器，绑定本 ADR 与 core-012 显式纳入 public Schema 许可，不扩大其他 public 新对象许可。
5. 创建和更新日期由数据库维护；视图追加真实 created_at/updated_at。角色关联实际变化同步更新用户日期；ON CONFLICT DO NOTHING 不制造更新时间。字段仍只读，客户端提交日期不可信。视图现有 dept_id 字段创建与更新写入 users 同名 UUID 字段，仍受现有外键约束和锁定保护。

## 验证、升级与回退

使用临时 tmpfs PostgreSQL 与独立 PostgREST 容器，验证两个 login RPC 的状态、签名、权限和租户契约；验证表/视图/角色绑定绕过、解锁独立性、服务器日期与事务回滚。不得使用现有业务数据库卷。

core-012 增加迁移终点、表触发器与视图字段，会产生真实 Catalog/OpenAPI/release provenance drift。历史冻结 SQL、baseline 和 DB2–DB7 release manifest 不得修改或重算 checksum；正式发布前需要独立候选契约和审批。回退采用发布前备份恢复，禁止删除约束后假称恢复了数据一致性。

本迁移约束新登录，不撤销已签发 JWT。生效用户改回创建/停用后，既有会话最多仍可使用原两小时有效期的令牌；实时撤销需要独立会话策略，不能把本次修复描述成全链路实时账户封禁。
