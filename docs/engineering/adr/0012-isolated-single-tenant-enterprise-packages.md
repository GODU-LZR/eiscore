# ADR-0012：首批企业采用隔离单租户部署与同源企业包

- 状态：接受
- 日期：2026-09-03

## 背景

EISCore 首批需要支持伦度机电、君乐缘和经纬网厂。当前数据库与企业站契约均以单个 `site_key=primary` 为边界，现有鉴权、缓存、域名和恢复流程没有共享数据库多租户的隔离证据。把三家企业复制成三个源码分支会重新形成客户硬编码和不可合并差异；直接扩展为共享多租户则会同时扩大 RLS、缓存、密钥、域名和灾难恢复范围。

用户于 2026-09-03 确认首批选择“三家企业独立部署、共用同一核心制品”。

## 决策

1. 伦度机电、君乐缘和经纬网厂分别使用独立数据库、运行环境、域名、密钥和备份恢复边界。一套部署只服务一家企业，不在首批引入共享数据库多租户。
2. 三套环境运行由同一 Git 提交一次构建得到的核心前后端制品。企业切换只能替换外部企业包；核心 JS/CSS、Node 运行时代码和容器镜像摘要不得随客户变化。
3. 企业包是受版本控制和校验的部署输入，不是源码分支。企业包分为：
   - 运行配置：企业内部标识、产品标题与主题、服务端点、模块和功能开关；
   - 初始化数据：企业站页面、产品、SEO 和经授权内容的可重复 Seed；
   - 素材：带来源、授权状态、哈希和用途的版本化文件；
   - Manifest：包版本、企业 ID、核心兼容范围、文件清单、校验和和审计信息。
4. 已发布 `company_site.site_config` 继续是企业公开资料唯一运行时事实源。企业包 Seed 只负责新环境初始化或显式迁移，初始化后由“企业站点运营”维护和发布，不形成第二个日常编辑入口。
5. 现有企业运行配置 v1 保持只读兼容；其 `branding.login` 扩展字段只用于迁移旧部署。新企业包必须使用 v2 最小运行配置，不允许携带导航、指标、业务链、能力、领导、公开文案等企业站资料。v2 登录页只从企业内部标识、产品主题、Logo 和中性系统文案启动，已发布档案加载后再覆盖公开企业身份。
6. 企业包不得包含密码、Token、API Key、私钥或环境专属秘密。秘密由每套隔离环境的服务端秘密配置提供，Manifest 只记录非秘密引用和校验结果。
7. 伦度机电、君乐缘和经纬网厂的候选包必须显式标注事实确认和素材授权状态。未确认字段不能用猜测值或看似真实的占位数据掩盖。

## 兼容、升级与回退

- v1 解析与现有 `eiscore-enterprise.json` 保持行为兼容，不静默删除历史字段。
- v2 由独立 Schema 和运行时分支显式识别；未知版本、把 v1 公开内容字段放入 v2、未知模块或秘密字段均失败关闭。
- 从 v1 升级到 v2 时先发布企业站档案，再挂载 v2 运行配置；回退可以重新挂载此前校验通过的 v1 配置和原企业包版本，不修改数据库已发布档案。
- 企业包升级只允许以新版本目录和 Manifest 发布，不覆盖历史包；恢复时同时指定核心制品摘要、企业包版本和数据库恢复点。

## 验收后果

G4 不能以“三份配置能通过 JSON Schema”作为完成。退出前必须证明一次构建的核心制品哈希在三套隔离环境一致，并分别验证配置失败关闭、模块依赖、企业站发布生命周期、实际启用业务链和包升级/回退。共享多租户属于未来独立 ADR，不在本阶段暗中引入。
