# EISCore 系统性重构最终报告

> 状态：进行中。G0～G3.5 及其后的企业资料合并检查点已完成，G4.0 已开始，G5 未开始；本报告仅在 G0-G5 全部验收后定稿。

## 1. 执行摘要

截至 2026-09-03，G0～G3 已建立仓库可信、变更安全、平台边界和核心可维护性门禁；G3.5 已在不接触原仓库和既有 WSL 数据卷的独立全栈中完成产品级集成与功能验收。G3.5 后又完成企业资料与企业站点运营的单一来源合并检查点；用户已确认三家隔离单租户、共用同一核心制品的首批拓扑，G4.0 配置边界开始，G5 尚未开始。

这证明重构后项目在代表性本地工程环境中可以构建、启动并完成已覆盖业务；它不等于生产发布批准。真实 AI 上游、三家企业配置包、客户数据迁移、恢复演练和发布运行治理仍属于后续 G4/G5。完整栈证据、哈希和限制见 `G3_5_EXIT_AUDIT.md`，后续资料合并证据见 `ENTERPRISE_PROFILE_MERGE_EXIT_AUDIT.md`，当前可运行性与待测边界见 `PRE_G4_ENGINEERING_READINESS.md`。

## 2. 范围与兼容边界

- 保留全部既有业务成果和对外行为。
- 保留 Vue、qiankun、PostgREST、PostgreSQL 和 Node.js 技术基础，除非 ADR 另有批准。
- 企业差异通过配置、功能开关和初始化数据表达。
- 原始仓库全程保持只读，全部重构在独立仓库完成。

## 3. 架构变化

已建立无业务依赖的 `@eiscore/platform` 包，企业配置 v1 通过同一入口完成校验、规范化、递归冻结和加载；品牌、端点、10 个模块与功能开关具备版本化契约。后续继续汇总 HTTP/Auth/Storage、核心模块和数据迁移变化。

基座已在 Vue 挂载前加载企业配置，正式构建运行时缺失配置会失败关闭；qiankun 保持 9 个原有子应用默认启用，并支持按企业模块开关过滤注册和传递只读配置。

模块开关已统一控制基座菜单、预热、历史标签、跨窗口标签、直达路由和移动设备跳转，禁用模块不会被基座注册或恢复入口。

已按真实回退入口与业务链建立 10 个企业模块的无环依赖契约，部署配置不能启用缺少必需下游模块的组合；应用中心的可选遗留跳转不反向强制全部模块启用。

已建立不依赖 Vue 的平台导航服务：仅接受安全的同源绝对路径，在跳转前统一执行企业模块开关检查，并分别适配 qiankun 宿主标签导航与子应用独立运行。销售到采购需求、出货申请和销售出库三条真实入口已作为首个迁移试点，原路径及查询参数保持不变，禁用目标模块时不再误跳转。

企业登录品牌最初从桌面 Store、桌面登录、系统设置和移动登录四处重复实现迁入部署配置。企业资料合并检查点进一步纠正了“部署配置与 `app_settings` 都能覆盖公开企业事实”的重复：已发布 `company_site.site_config` 现在是企业名称、Logo、公开联系方式、域名、主题和 SEO 的唯一运行时事实源；`app_settings` 仅保存内部系统偏好，部署配置和旧 `loginBranding` 只承担启动与无发布档案时的兼容兜底。系统设置改为只读摘要，企业站点运营统一编辑、草稿和发布；边界见 ADR-0011。

合并检查点完整保留君乐缘球杆配置器/材料资产和经纬网厂独立站/研究资产，并把企业站纳入基座导航、Runtime 模块和平台档案服务；后续复核补齐君乐缘 42 个 V2/V3 材料文件，保留 14 个 V1 JPEG 作为历史兼容回退。生命周期测试证明“保存草稿 → 发布 → 公开 API → 基座重新加载”闭环；完整质量门禁、单元总集、企业站 26/26、28 表 Schema、80 条 Runtime 路由、252 个 Node 文件语法以及企业站加入后的 12/12 前端生产构建均通过。合并后分别完成状态化双前端 Chromium 1/1、不 mock API 的 PostgreSQL/PostgREST/Agent/双 Vite 完整栈 1/1，以及君乐缘材质 Chromium 1/1，覆盖真实登录、系统设置只读、运营跳转、两次保存草稿、发布快照和域名隔离、发布同步、刷新、停用 404、无发布档案时不再显示旧回退编辑器，并实际验证 V2 材质卡及 V3 枫木/黑檀纹理应用到 Three.js 材质。合并时发现的 4 个直接浏览器存储消费者也已迁入平台安全存储/会话边界，没有扩大 G2 白名单。当前 Realtime 组合根为 796 行、31 个模块和 28 个辅助职责；SQL 库存为 107 份、Runtime V2 的 10 份及 company-site 的 1 份受迁移 Manifest 治理；Vue 库存为 148 个文件、51 个巨页和 83,332/85,045 行债务。详细证据见 `ENTERPRISE_PROFILE_MERGE_EXIT_AUDIT.md` 与 `JUNLEYUAN_LATEST_RESULT_MERGE_AUDIT.md`。

已建立产品级平台 HTTP 契约：请求地址只能由企业端点配置与安全资源路径组合，认证信息通过适配器注入，默认超时、401 通知和错误分类保持一致，错误消息不会包含查询参数、Token、请求体或服务端响应。桌面系统配置读写和移动登录配置读取已完成首个真实链路迁移；平台层不自动重试写请求。边界决策见 ADR-0003。

已建立平台 Auth/Session 与安全存储契约：继续读取纯文本和 JSON 两种存量 Token，统一 UTF-8 Base64URL JWT 解码、严格过期判断、长度上限和双 Key 清理；Storage 禁用、配额不足或损坏 JSON 均失败关闭且不泄露 Key/Value。企业站加入后，基座、移动端及 9 个微应用共 11 份 Auth 工具均已保留原导出和登录路径迁入薄适配器；企业站管理端 Request 和四类本地偏好/草稿也分别进入平台 HTTP 与安全存储边界。平台层不承担导航或 JWT 签名校验。边界决策见 ADR-0004。

已建立无 Vue 与 Storage 依赖的平台权限服务，基座及 8 个微应用共 9 个权限工具改为薄适配器。通用权限集合、`app_role`/`appRole`/`role`、`super_admin`、销售/采购模块授权与经理角色特例、读错降级差异及原导出保持；平台判断只负责前端可见性，不替代服务端授权。G2 退出审计同时确认企业配置、Auth/Session、普通受保护 HTTP、基础设施错误边界和前端权限判断已具备退出证据，并量化剩余非会话 Storage 16 个文件/58 处、全页导航 20 个文件/24 处及 8 份共享 Grid 副本。边界决策见 ADR-0005。

全产品直接 `fetch` 已建立精确库存门禁：`eiscore-*/src` 与 `shared/` 只允许 23 个文件中的 84 处既有调用，按 Geo/翻译混合、Agent 协议、静态资源、服务探测、登录启动和兼容 Auth 六类锁定，普通受保护 API 调用为 0。任何新增文件、次数漂移或非登录/兼容代码新增字面 `/api` 请求都会阻断质量门。证据满足后，基座对 `window.fetch` 的全局 401 猴子补丁已删除；普通 API 的会话清理继续由宿主平台客户端局部闭环，登录、流式、外部服务和静态资源不再承受隐式全局副作用。

AI Bridge、Home、DigitalTwin、移动企业助手和移动仓库助手的五个 SSE 请求已提取为共享可取消 Agent 边界。共享层只允许 `/agent/`、执行 POST/JSON、透传 AbortSignal 并按既有换行规则分帧；AI 路由头与静默重试、Twin 工具/会话事件、移动 Delta、三种错误正文上限及无效 JSON 策略继续留在消费者。组件卸载或 AI 模式重置会中止旧流且不落错误消息，页面级 Agent 传输归零，总库存降至 12 个文件、18 处。

平台 HTTP 新增注入式 Axios 兼容层，质量与设备成为首批 Request 迁移试点。兼容层在 Axios 适配器执行前强制把资源地址重新映射到企业端点，完整 URL 也只有严格位于已配置服务根下才可使用；现有可调用 config、`response.data`、Profile、超时、401 和错误对象身份保持。通知、结构化事件及拒绝错误的可序列化配置会移除认证头、请求体和查询值，平台包仍不直接依赖 Axios 或 Element Plus。

仓储 Request 的动态 Schema 路由迁入后，14 个库存/仓储端点仍默认 `scm`，其他端点默认 `public`。分类只读取平台提供的不含查询资源路径，不受企业 API 域名或租户前缀重写影响；调用方显式 Profile 继续优先。至此 8 个微应用的重复 Axios 拦截器全部收敛。

基座最后一份 Axios Request 通过自动服务模式迁入：兼容调用必须显式以 `/api` 或 `/agent` 开头，再映射到企业配置的对应端点；未配置根路径拒绝。AI `/agent/ai/` 401 继续与主会话隔离，普通 API 401、404 探测静默和断网文案保持。产品源码中的 9 份 Axios Request 至此全部统一。

下一阶段是否进入 G4 由用户另行决定。进入 G4 时应优先建立伦度机电、君乐缘、经纬网厂的版本化配置与差异矩阵，不应修改已通过的 G3.5 基础运行行为；G5 再处理制品、恢复、发布、可观测性和性能预算。
