## 3. 架构变化

已建立无业务依赖的 `@eiscore/platform` 包，企业配置 v1 通过同一入口完成校验、规范化、递归冻结和加载；品牌、端点、10 个模块与功能开关具备版本化契约。后续继续汇总 HTTP/Auth/Storage、核心模块和数据迁移变化。

基座已在 Vue 挂载前加载企业配置，正式构建运行时缺失配置会失败关闭；qiankun 保持 9 个原有子应用默认启用，并支持按企业模块开关过滤注册和传递只读配置。

模块开关已统一控制基座菜单、预热、历史标签、跨窗口标签、直达路由和移动设备跳转，禁用模块不会被基座注册或恢复入口。

已按真实回退入口与业务链建立 10 个企业模块的无环依赖契约，部署配置不能启用缺少必需下游模块的组合；应用中心的可选遗留跳转不反向强制全部模块启用。

已建立不依赖 Vue 的平台导航服务：仅接受安全的同源绝对路径，在跳转前统一执行企业模块开关检查，并分别适配 qiankun 宿主标签导航与子应用独立运行。销售到采购需求、出货申请和销售出库三条真实入口已作为首个迁移试点，原路径及查询参数保持不变，禁用目标模块时不再误跳转。

企业登录品牌已从桌面 Store、桌面登录、系统设置和移动登录四处重复实现迁入部署配置。平台适配器统一企业名称、Logo、主题、登录文案、指标、业务链、能力、轮播图、管理团队及移动差异字段；管理员保存在 `app_settings` 的运行期设置继续作为覆盖层。当前登录页成果完整保存在兼容配置数据中，产品源码不再包含客户名称或客户素材域名。移动端也在 Vue 挂载前加载企业配置，正式制品配置错误时失败关闭。

已建立产品级平台 HTTP 契约：请求地址只能由企业端点配置与安全资源路径组合，认证信息通过适配器注入，默认超时、401 通知和错误分类保持一致，错误消息不会包含查询参数、Token、请求体或服务端响应。桌面系统配置读写和移动登录配置读取已完成首个真实链路迁移；平台层不自动重试写请求。边界决策见 ADR-0003。

已建立平台 Auth/Session 与安全存储契约：继续读取纯文本和 JSON 两种存量 Token，统一 UTF-8 Base64URL JWT 解码、严格过期判断、8192 字符上限和双 Key 清理；Storage 禁用、配额不足或损坏 JSON 均失败关闭且不泄露 Key/Value。基座、移动端及 8 个微应用共 10 份 Auth 工具均已保留原导出和登录路径迁入薄适配器，平台层不承担导航或 JWT 签名校验。边界决策见 ADR-0004。

会话契约已接入首批真实失效链：基座全局 API 401、移动路由守卫和仓库/库存/考勤/盘点 API 均通过适配器清理会话。原 `/login`、`/mobile/login`、移动重定向参数、401 用户错误及宽松 JWT 路由兼容保持，移动端这些链路不再直接操作 Storage 或 Base64；剩余直接会话操作已量化为基座 9 个文件、30 处。

基座用户 Store 已通过平台会话完成初始化、登录持久化和退出清理。平台显式区分桌面 `plain` 与移动 `json` Token 写入格式，因此结构收敛没有改变既有部署中的存储表示；历史两种格式仍可互读。剩余直接会话操作进一步降为基座 8 个文件、24 处。

基座布局与权限工具已接入平台会话。布局仍以相同 `user_info` Key 响应跨窗口 `storage` 事件，并以 500ms 原始文本轮询捕获同窗口更新；认证头、超长 Token 清理、UTF-8 JWT、用户查询回填和头像刷新统一复用平台能力。超级管理员与权限数组判定规则保持，剩余直接会话操作降为基座 6 个文件、12 处。

AI Copilot、AI Bridge、设置、首页、数字孪生和 qiankun 用户状态桥完成了基座最后一批已盘点迁移；AI 的宽松过期规则、页面 JSON 头、设置认证头和微前端事件时序均由回归契约保护。后续全产品复审发现早期“产品源码归零”结论口径不完整：微应用页面、Store、权限、Realtime 和共享 Grid 副本仍有 56 个文件、134 处直接会话调用。报告已纠正，加入只降不增门禁，Auth/Session 子目标继续进行而非完成。

纠正基线后的首批迁移覆盖 8 个微应用用户 Store。各 Auth 适配器统一提供用户信息读写，Pinia Store 不再自行解析或写入 LocalStorage；质量/设备的空值规范化差异继续保留。直接会话调用降至 48 个文件、118 处。

8 个微应用的权限与 Realtime 工具随后完成会话适配。权限判定改由 Auth 适配器提供用户信息，`super_admin`、销售/采购模块授权与经理角色特例及各应用原导出保持；Realtime 改取规范化 Token，但开发/代理 WebSocket 地址、Bearer 子协议、重连周期和关闭能力差异均未改变。直接会话调用进一步降至 32 个文件、87 处。

8 份共享 Grid 与 GeoDialog 副本也已接入 Auth 适配器。Grid 仍优先使用响应式 Store，只在空用户对象时读取最新会话快照；权限与角色派生保持。Geo 的 JSON/Bearer 鉴权、定位、截图、外部地图/IP 和 GLM 翻译流程未变，各模块业务扩展副本继续独立保留。直接会话调用降至 16 个文件、71 处。

生产、人事与仓储的 6 个局部消费者随后完成迁移。生产首页及业务 Grid 统一认证头和审计用户读取；HR 用户资料更新在安全持久化后继续广播窗口、文档、父窗口、StorageEvent 与 qiankun 状态；两份入口权限指令和仓储盘点人保持原规则。直接会话调用降至应用中心 10 个文件、61 处。

应用中心 Flash 运行时桥接、草稿预览和 Builder 已接入 Auth 适配器。桥接层独有的 Token 去空格、两套用户缺失回退、用户名/角色别名、写工具白名单、幂等与 Agent 双地址行为保持。直接会话调用降至 7 个文件、56 处。

应用配置中心与 DataApp 的 8 个请求鉴权点已改取规范化 Token。既有 Axios 调用、`app_center` Profile、RLS 识别、只读应用规则、创建回写、数据表 RPC 与发布路由保持，本切片未混入 HTTP 客户端替换。直接会话调用降至 5 个文件、48 处。

Agent 示例客户端的 9 个 Token 读取点已改取平台会话。动态主机与 localhost 两种 8078 WebSocket 地址、Bearer 子协议、消息载荷、事件处理、两分钟超时和 CommonJS 兼容导出保持。直接会话调用降至 4 个文件、39 处。

简单流程设计器、审批中心与完整 FlowDesigner 的 19 个直接会话点已统一到平台会话。`app_center`、`workflow`、`public` Profile、审批用户角色别名、拒绝/流转 RPC、BPMN 定义、任务分配、状态映射、业务绑定和发布路由均保持。直接会话调用降至 AppRuntime 单文件、20 处。

AppRuntime 的 20 个直接会话点已迁移，原有 Token 去空格 helper、用户角色别名、Flash 草稿注入、动态 schema Profile、流程启停/流转、权限策略与授权流程保持。全部 `eiscore-*/src` 产品目录已归零；本切片同时把库存门禁扩展到根部 `shared/`，纠正此前范围遗漏，并识别出仍被多微应用引用的 3 个文件、3 处调用。

根部共享显示控制、应用卡片统计与 Grid 操作审计已接入新的共享平台会话适配器，适配器直接复用 monorepo 平台实现；显示缓存/事件、可选 Bearer、精确计数/RPC 回退、8192 Token 上限、审计用户别名与 `unknown` 回退保持。生产运行时代码中的直接 `auth_token`/`user_info` LocalStorage 消费全仓归零，并由覆盖 `eiscore-*/src` 与 `shared/` 的严格门禁持续保护；显式写会话的 E2E 登录夹具不在生产门禁范围。

基座平台适配器现公开可复用 HTTP 客户端，设置页的动态应用列表及 Agent 配置读写 3 个受保护请求已接入平台 HTTP/系统配置服务。企业端点、15 秒默认超时、安全错误与局部 `/login` 401 清理开始覆盖该页；管理员短路、`app_center`/`public` Profile、Agent 字段/描述、脏状态和保存失败布尔语义保持。

采购单据关系的可选查重与写入链路已从直接 `fetch` 迁入采购平台 Request。`public` Profile、`return=representation`、业务键查重及失败返回 `null` 保持；请求级静默选项只抑制可选链路的错误气泡，401 仍执行统一会话清理与 `/login` 跳转。

根部共享显示配置与应用卡片精确计数已接入新的共享平台 HTTP 适配器。适配器按企业配置缓存客户端、统一 Token 与局部 401 失效，`shared/` 不再直接调用 `fetch` 或拼装认证头；显示缓存/事件、`count=exact`、`Range: 0-0`、`Content-Range` 总数解析及 RPC 回退保持。

基座 SOP 学习记录的读取与 upsert 已接入宿主平台 HTTP 客户端。按用户名读取、500 条上限、`public` Profile、冲突合并和同步状态机保持；远程不可用时仍安静降级到本地进度，401 则由宿主适配器统一清理并跳转登录。

基座布局中的超级管理员角色/数据范围、文件头像及用户资料四路回退也已接入宿主平台客户端。显式 Token 回退、Base64 头像、6 个范围模块和原字段优先级保持；数据范围失败不再误标为已同步，而是继续使用既有最多 3 次重试。布局直接 `fetch` 严格收敛为资产清单与预热两个静态资源调用。

AI Copilot 的动态模板库和物料分类配置读写已接入宿主平台客户端。动态 Key、作用域、冲突合并、宽松 Token 过期判断及 UI 状态保持；模板读取失败继续为空库，分类读取失败继续按空配置保存，写入错误仍区分“登录已过期”和“保存失败”。

AI Copilot 的智能 BI 行动单列表读取也已接入宿主平台客户端。字段投影、更新时间倒序、120 条上限和并发保护保持；任何失败或非数组响应仍回退为空列表。

AI Copilot 的物料批次号查询与动态表数据导入已接入宿主平台客户端。动态目标移除兼容 `/api` 前缀后受企业端点与安全路径约束；分类起号、Profile、显式 Token、401 专用提示、跳过统计和导入完成事件保持。HTTP 非 2xx 的批次查询仍按空结果回退，网络/超时仍中止导入。

平台 HTTP 新增注入式 Axios 兼容层，质量与设备成为首批 Request 迁移试点。兼容层在 Axios 适配器执行前强制把资源地址重新映射到企业端点，完整 URL 也只有严格位于已配置服务根下才可使用；现有可调用 config、`response.data`、Profile、超时、401 和错误对象身份保持。通知、结构化事件及拒绝错误的可序列化配置会移除认证头、请求体和查询值，平台包仍不直接依赖 Axios 或 Element Plus。

默认 `public` Profile、标准 401 实现族进一步覆盖采购 Request。采购调用方和业务链无需修改，5000ms 超时、显式 Profile 覆盖与错误响应读取保持，所有请求开始受相同企业端点和脱敏规则约束。

销售 Request 迁移时，平台兼容层增加请求级通知判定。既有 `silentError`、`suppressErrorMessage` 继续抑制错误气泡，但不会抑制 401 的会话清理与 `/login` 跳转；其他 Axios 行为、5000ms 超时和 `public` Profile 保持。

人事与应用中心两个标准错误实现进一步迁入平台兼容层。人事继续默认 `hr` Profile 与 5000ms，应用中心继续默认 `app_center` Profile 与 8000ms，调用方显式 Profile 始终优先。

生产 Request 使用 `scm` Profile 迁入时，平台兼容层增加显式、受控的业务错误映射：正常短业务提示保持；带秘密字段标记、URL/查询结构、控制字符或过长的服务端文本不会进入 UI 通知。该策略落实 ADR-0003 对用户可见业务校验的单独映射要求。

仓储 Request 的动态 Schema 路由迁入后，14 个库存/仓储端点仍默认 `scm`，其他端点默认 `public`。分类只读取平台提供的不含查询资源路径，不受企业 API 域名或租户前缀重写影响；调用方显式 Profile 继续优先。至此 8 个微应用的重复 Axios 拦截器全部收敛。

基座最后一份 Axios Request 通过自动服务模式迁入：兼容调用必须显式以 `/api` 或 `/agent` 开头，再映射到企业配置的对应端点；未配置根路径拒绝。AI `/agent/ai/` 401 继续与主会话隔离，普通 API 401、404 探测静默和断网文案保持。产品源码中的 9 份 Axios Request 至此全部统一。
