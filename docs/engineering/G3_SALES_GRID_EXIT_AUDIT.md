# G3 SalesAppGrid 阶段退出审计

## 结论

`SalesAppGrid.vue` 的纯策略拆分阶段通过退出审计。页面从 G3 起点的 4,534 行降至 3,822 行，减少 712 行（15.7%）；数据聚合、详情投影、销售单据下推和四类快速录单规则已进入 4 个无 Vue、Element Plus、Request、Axios、浏览器或 Storage 依赖的纯模块，共 40 个具名导出。

该结论关闭的是 SalesAppGrid 当前纯策略子目标，不等于把页面降到普通组件规模。页面仍是 833 行模板、2,541 行组合脚本和 445 行局部样式；Grid 协议、查询 Service、Composable 或视觉组件的后续拆分必须由真实交互回归或明确复用收益驱动。本阶段转向当前更大的高风险巨页。

## 接受门槛

| 门槛 | 结果 | 持续证据 |
| --- | --- | --- |
| 页面不得超过退出基线 | 通过：3,822 行 | 组合退出门禁与 Vue 复杂度棘轮 |
| 模板、脚本、样式不得反弹 | 通过：833 / 2,541 / 445 行 | SFC 分区上限门禁 |
| 核心决策离开组合页 | 通过：4 个纯策略模块、40 个导出 | 精确 Domain Import 与依赖门禁 |
| 直接协议与 UI 副作用不再增长 | 通过：53 个 Request、57 个消息/确认、1 个本地 Router 调用 | 逐类上限门禁 |
| 不重新引入平台旁路 | 通过：无直接 Fetch、Axios、Storage、EventSource、WebSocket、XMLHttpRequest 或 `window.location` 导航 | 禁止访问门禁 |
| 页面局部可调用职责不增长 | 通过：124 个组合/展示 Callable、8 个 Watch | 声明数量上限门禁 |
| 生命周期入口保持稳定 | 通过：2 个 Mounted、1 个 Unmounted | 生命周期精确门禁 |
| 离线完整验证 | 通过 | `test:quality`、`test:unit` 与销售生产构建 |

## 页面保留职责

- 维护 Vue Ref/Reactive/Computed/Watch、Drawer、Dialog、Grid 选择和加载状态。
- 执行 53 个平台 Request 读写点及其 Profile/Header、消息、确认、审计和刷新顺序。
- 装配 Realtime 订阅、延迟刷新、AI/Grid 窗口事件和卸载清理。
- 生成单据号与当前日期，把纯策略计划适配到 Request、Router 和企业导航。
- 保留 833 行现有模板和 445 行 Scoped Style，避免无浏览器证据的视觉漂移。

这些职责是当前销售 Grid 页面的组合和展示边界。继续拆分它们需要真实业务链、浏览器交互或明确的跨页面复用证据；只按物理行数拆分会扩大请求时序、响应式依赖和样式作用域风险。

## 非阻断项

- 页面仍显著高于 800 行审查阈值，逐文件与总债务棘轮继续禁止增长。
- 53 个 Request 调用仍位于组合页；新增协议必须进入小型 Service/Adapter，后续可按 API 族在隔离环境验证后迁移。
- 模板、Watch 和样式尚未拆视觉子组件；本阶段没有浏览器端业务数据和截图证据，因此接受保留。
- 既有快速录单校验失败后仍会关闭弹窗并刷新；为避免把行为修复混入重构，本阶段按现状锁定，后续应作为独立产品缺陷处理。
- 未连接数据库、PostgREST、Realtime 服务或企业环境；销售订单、回款、商机、跟进与采购/出库链路仍需隔离环境演练。
- 当前验证机为 Node 26.1.0 / npm 11.13.0；发布证据仍要求 Node 20.19.0 / npm 10.8.2。
