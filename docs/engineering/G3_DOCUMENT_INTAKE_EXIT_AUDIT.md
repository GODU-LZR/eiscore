# G3 DocumentIntakeCenter 阶段退出审计

## 结论

`eiscore-base/src/views/DocumentIntakeCenter.vue` 的纯策略拆分阶段通过退出审计。页面从 G3 起点的 2,446 行降至 1,973 行，减少 473 行（19.3%），并退出 ≥2,000 行极端页层级；展示/总览动作、默认筛选/跨列表跳转、监听目录、入库结果详情、设备操作和四类列表查询已进入 6 个无 Vue、Element Plus、网络、浏览器、Storage 或隐式时间依赖的纯模块，共 54 个具名导出。

该结论关闭的是 DocumentIntakeCenter 当前纯策略子目标，不等于把页面降到普通组件规模。页面仍有 1,058 行模板、647 行组合脚本和 260 行局部样式；四类大表、两个 Drawer、13 个真实 API 操作、确认/消息、Clipboard 回退和请求并发时序的后续拆分必须由真实收单数据、设备状态和浏览器截图基线驱动。G3 转向当前更大的未退出高风险巨页。

## 页面保留职责

- 维护 Vue Ref/Reactive/Computed/Watch，以及四个列表、筛选条、分页、两个 Drawer 和 Loading/Error 状态。
- 通过既有收单 API 边界执行总览、四类列表、详情、设备状态/授权码和监听目录共 13 个真实操作，保留请求序号、过期响应丢弃、失败清空与刷新时序。
- 装配设备启停/重置和目录保存/启停/删除的确认、成功/失败消息，以及授权码 Clipboard/Alert 回退。
- 通过平台导航打开业务记录，并保留服务器 URL 优先、未知目标禁用和复制业务记录 ID 行为。
- 保留 1,058 行现有模板和 260 行 Scoped CSS，避免无真实文件、设备、日志、入库结果与多分辨率截图证据的表格、Drawer 和移动布局漂移。

这些职责是当前 DocumentIntakeCenter 的组合、网络和展示边界。继续拆分需要成功/部分/失败/重复入库、低置信度、设备离线/停用、授权码 Clipboard 失败、目录 CRUD 错误和多分辨率截图证据；只为继续降行数拆模板、样式或异步闭包会扩大回归风险。

## 非阻断项

- 页面仍高于 800 行巨页阈值，逐文件与总债务棘轮继续禁止增长；本阶段接受原因是剩余模板以真实表格/Drawer 布局为主，脚本以 API 与响应式编排为主。
- 13 个网络操作全部通过既有 `document-intake-api.js` 边界；新增协议不得继续内联，六组专项会阻止已迁出规则回流。
- 当前只验证离线策略、UI 文本契约和基座构建，未访问数据库、远程 API、采集器或企业环境。
- 当前验证机为 Node 26.1.0 / npm 11.13.0；发布证据仍要求 Node 20.19.0 / npm 10.8.2。
