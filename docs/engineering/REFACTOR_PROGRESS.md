## 不可变约束

- 原始仓库保持只读；重构只在独立仓库的 `codex/systematic-refactor` 分支进行。
- 起始检查点为 `e5d0b92`，包含全部已确认的最新业务成果和前三个工程化切片。
- 不向任何远端推送，除非用户后续明确授权。
- 不整体重写；先用特征测试保护行为，再按业务切片渐进迁移。
- 不运行可能写入真实环境的 `:remote` 测试，除非用户明确授权目标环境和数据写入。
- 每个切片必须形成小提交，并记录实际验证、未验证项和剩余风险。

## 当前切片

- 状态：G2 进行中；采购单据关系的可选查重与写入链路已完成 HTTP 边界迁移。
- 结果：两处直接 `fetch` 及自行拼装认证头改用采购平台 Request；请求地址受企业端点约束，认证、Profile、错误脱敏与 401 会话失效复用统一适配器。
- 兼容边界：`public` Profile、`return=representation`、写入前按业务键查重和任意失败静默返回 `null` 均保持；`silentError`/`suppressErrorMessage` 只抑制错误气泡，不抑制 401 清理与 `/login` 跳转。
- 验证：完整质量门禁通过，覆盖 92 个 Node 脚本、14 个 CI 包、采购业务流及既有平台 HTTP 契约、1153 个文本秘密扫描、8 个变更代码文件 lint、23 个 Shell 与生产 Compose；采购生产构建成功并转换 1629 个模块。

## 已知非阻断风险

- 当前 npm 对 `esbuild`、`@parcel/watcher`、`vue-demi`、`sharp` 等第三方安装脚本给出未显式批准告警；现有 11 个前端构建仍全部成功。
- 多个前端共享构建配置报告 `vendor-misc` 与 `vue-runtime` 循环分包，应在公共构建边界单独治理。
- `eiscore-apps` 的 BPMN 主块约 1.57 MB，存在首屏加载与缓存更新成本。
- 部分依赖出现弃用或 Rollup/Sass 兼容告警，需要纳入依赖升级策略，不能与业务重构混合处理。
- 生产部署脚本仍包含 `npm install` 和全局 PM2 安装，属于 G5 可重复部署治理范围。
- Auth/Session 消费者已在全部 `eiscore-*/src` 与根部 `shared/` 归零，质量门禁禁止生产运行时代码重新直接访问 `auth_token`/`user_info`；E2E 登录夹具保留显式会话写入。
- 平台 HTTP 已覆盖系统配置、全部 9 份 Axios Request、基座设置页 3 个受保护调用及采购可选业务流；其余直接 `fetch`、基座全局 401 兜底及其他局部客户端仍需按静态资源/登录/Agent/外部服务/受保护 API 分类收敛。
- 2026-08-30 全产品复审纠正了早期会话统计口径：此前“归零”只覆盖基座/移动与 Auth 工具，没有覆盖微应用页面、Store、权限、Realtime 和共享 Grid 副本。产品目录审计基线为 56 个文件、134 处直接调用；连续九个切片后依次降至 118/48、87/32、71/16、61/10、56/7、48/5、39/4、20/1、0/0。AppRuntime 切片把门禁扩展至根部共享运行时代码并发现范围外 3/3，本切片已将其归零；Auth/Session 子目标完成。
- 销售→采购/仓储试点已迁入平台导航服务；其他业务页面仍有直接跳转和具体路径，须按真实业务链逐步迁移。
- 当前兼容配置仍引用既有第三方 HTTPS 图片地址；建立三家企业配置包时应把获授权素材镜像到企业自有静态资源域名并验证可用性。
