# G3 基座布局阶段退出审计

## 结论

`eiscore-base/src/layout/index.vue` 的纯策略拆分阶段通过退出审计。页面从 G3 起点的 4,003 行降至 3,535 行，减少 468 行（11.7%）；宿主标签路由、微应用预热、布局壳和引导规范化已进入 4 个无 Vue、Element Plus、网络、浏览器、Storage 或隐式时间依赖的纯模块，共 41 个具名导出。

该结论关闭的是基座布局当前纯策略子目标，不等于把页面降到普通组件规模。页面仍有 248 行模板、2,908 行组合脚本和 376 行局部样式；身份权限、微应用加载、SOP DOM/Driver、进度同步、宿主标签和窗口事件的后续拆分必须由真实登录态与多微应用交互证据驱动。G3 转向当前更大的未退出高风险巨页。

## 页面保留职责

- 维护 Vue Ref/Computed/Watch，以及菜单、主题、加载遮罩、引导中心、欢迎弹窗和宿主标签状态。
- 通过平台 Auth/Permission/HTTP/Storage/Navigation 边界保留身份补全、超级管理员范围、头像、SOP 学习记录和标签持久化。
- 请求静态资产 Manifest 并按 4/5 并发、Apps 优先、后台候选和 Full 升级规则执行真实预热。
- 查询可见 DOM、观察微应用挂载、装配 Driver 步骤并处理动态 SOP 动作、流程、表格、表单、文件和业务卡片。
- 保持 8 对窗口事件、两个生命周期装配区、MutationObserver、轮询、Timer、Router 与 qiankun 容器时序。
- 保留 248 行现有模板和 376 行 Scoped SCSS，避免无登录态截图与交互证据的菜单、弹层、标签、遮罩和响应式布局漂移。

这些职责是当前基座布局的组合、平台接线和展示边界。继续拆分需要登录、角色权限、九个微应用、跨窗口事件、Driver 引导和标签恢复的浏览器证据；只按物理行数移动大段 SOP 文案或 Composable 会扩大响应式闭包、DOM 引用和事件解绑风险。

## 非阻断项

- 页面仍显著高于 800 行审查阈值，逐文件与总债务棘轮继续禁止增长。
- 2 个静态 Fetch 仅用于资产 Manifest 与同源预热，受既有直接请求库存门禁保护；受保护业务 API 保持平台 HTTP 边界。
- 2,908 行组合脚本包含大量 SOP 元数据与 Driver 装配；本阶段没有三家企业真实角色、全微应用登录态或视觉基线，因此接受保留。
- 当前只验证离线策略和生产构建，未发起数据库、远程 API、微应用资源预热或企业环境请求。
- 当前验证机为 Node 26.1.0 / npm 11.13.0；发布证据仍要求 Node 20.19.0 / npm 10.8.2。
