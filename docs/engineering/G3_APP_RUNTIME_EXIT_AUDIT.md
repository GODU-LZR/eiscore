# G3 AppRuntime 阶段退出审计

## 结论

`AppRuntime.vue` 的纯策略拆分阶段通过退出审计。页面从 G3 起点的 4,934 行降至 3,725 行，减少 1,209 行（24.5%）；BPMN、Workflow、自动推进、导航、Flash 来源、权限与任务路由规则已进入 4 个无 Vue、Element Plus、Axios 或 Storage 依赖的纯模块，共 94 个具名导出。

该结论关闭的是 AppRuntime 的当前纯策略子目标，不等于把页面降到普通组件规模。页面仍是 849 行模板、2,167 行组合脚本和 706 行局部样式；协议 Service、Composable 或视觉组件的后续拆分必须由新的高价值职责和交互证据驱动，不能为了物理行数机械搬运。本阶段先转向风险更高且尚无同等保护的巨页。

## 接受门槛

| 门槛 | 结果 | 持续证据 |
| --- | --- | --- |
| 页面不得超过退出基线 | 通过：3,725 行 | 组合退出门禁与 Vue 复杂度棘轮 |
| 模板、脚本、样式不得反弹 | 通过：849 / 2,167 / 706 行 | SFC 分区上限门禁 |
| 核心决策离开组合页 | 通过：4 个纯策略模块、94 个导出 | 精确 Domain Import 与依赖门禁 |
| 直接协议与 UI 副作用不再增长 | 通过：29 个 Axios、60 个消息/确认、5 个本地 Router 调用 | 逐类上限门禁 |
| 不重新引入平台旁路 | 通过：无直接 Fetch、Storage、EventSource、WebSocket 或 `window.location` 导航 | 禁止访问门禁 |
| 页面局部可调用职责不增长 | 通过：118 个组合/展示 Callable | 声明数量上限门禁 |
| 离线完整验证 | 通过 | `test:quality`、`test:unit` 与应用中心生产构建 |

## 页面保留职责

- 维护 Vue Ref/Reactive/Computed、对话框、Picker、待办视图和加载状态。
- 执行 29 个 Axios 读写点及其 Profile/Header、消息、确认和刷新顺序。
- 装配 BPMN Viewer、DOMParser、自动推进 Timer、侧栏拖拽 Listener 和卸载清理。
- 把纯策略结果适配到模板标签、图标、文本、Router 与企业宿主导航。
- 保留 849 行现有模板和 706 行 Scoped Style，避免无浏览器证据的视觉拆分。

这些职责是当前运行时页面的组合和展示边界。继续拆分它们需要真实交互回归或明确的协议复用收益；在只有离线环境时强拆会扩大生命周期、样式作用域和渲染漂移风险。

## 非阻断项

- 页面仍显著高于 800 行审查阈值，逐文件与总债务棘轮继续禁止增长。
- 29 个 Axios 调用仍位于组合页；新增协议必须进入小型 Service/Adapter，后续可在真实环境验证后按 API 族迁移。
- 模板和样式尚未拆视觉子组件；本阶段没有浏览器交互或截图证据，因此接受保留。
- 未连接数据库、PostgREST、Agent、Cline 或企业环境；Strict、授权补齐、自动推进和业务记录跳转仍需隔离环境演练。
- 当前验证机为 Node 26.1.0 / npm 11.13.0；发布证据仍要求 Node 20.19.0 / npm 10.8.2。

## 回退与下一目标

十三个抽取切片均为独立提交，不包含数据、接口或部署变更，可按职责单独回退；回退会恢复对应页面内联实现并失去专项门禁。退出审计本身只增加离线门禁和文档。

G3 下一目标为 4,534 行的 `eiscore-sales/src/components/SalesAppGrid.vue`。它是当前最大 Vue 巨页，直接承载销售业务与 Grid 交互，应先建立职责库存和行为特征测试，再选择第一个无视觉变化的纯策略边界。
