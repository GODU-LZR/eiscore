# 企业独立站与系统个性化配置契约

## 目标

EISCore 首批以“伦度机电、君乐缘、经纬网厂独立部署，同一核心制品”为边界。个性化只允许通过版本化企业包进入，不复制客户源码，不把企业名称、域名、素材或业务差异写回核心代码。

实施运营台是配置设计、资料追溯、审核和交付控制面；EISCore 是配置校验、受控导入和运行数据面。公开企业资料只有一个运行时事实源：由“企业站点运营”显式发布的 `company_site.site_config` 及其关联内容。

## 配置分层

| 层级 | 文件或存储 | 所有者 | 内容 |
| --- | --- | --- | --- |
| 核心制品 | Git、前端/Realtime 镜像、数据库发布 Manifest | 产品工程 | Vue/Node 代码、PostgreSQL 表和函数、触发器、RLS、PostgREST 契约 |
| 系统部署个性化 | `runtime/eiscore-enterprise.json` | 实施/部署 | 企业内部标识、系统标题、Logo、主题色、端点、模块和功能开关 |
| 独立站初始化 | `data/company-site.json` | 实施运营台 | 企业公开身份、域名、模板、语言、SEO、联系方式、内容草稿及素材引用 |
| 独立站运营事实 | `company_site.*` | 企业站点运营人员 | 草稿、审核、发布、回滚、产品、页面、方案、案例、证据、SEO/GEO 和知识内容 |
| 权限与业务配置 | 受控配置包及数据库元数据 | 实施与企业管理员 | 动态应用、字段、流程、角色、权限、字典、编号和业务模板 |
| 环境秘密 | 环境变量或秘密管理系统 | 部署管理员 | 数据库密码、JWT、AI Key、对象存储凭据、证书私钥 |
| 个人偏好 | 安全本地存储或用户设置 | 最终用户 | 主题模式、布局、最近页面等个人体验设置 |

“模块启用”“菜单可见”和“数据权限”是三个独立概念：`modules` 决定某企业是否部署能力，界面可见性只影响展示，ACL/RLS 才决定用户能否访问数据。

## 系统部署个性化

企业包必须使用运行配置 v2。字段职责如下：

| 字段 | 用途 |
| --- | --- |
| `enterprise.id/displayName/shortName` | 部署内企业身份和系统兜底显示 |
| `branding.productName/themeColor/logoUrl` | EISCore 系统标题、主题和登录前的中性品牌兜底 |
| `endpoints` | 当前独立环境的公开根地址、PostgREST、Agent 和 WebSocket 路径 |
| `modules` | HR、物料、应用中心、企业站、销售、采购、生产、质量、设备、决策、移动端部署开关 |
| `features` | `documentIntake`、`enterpriseAi` 等模块内功能开关 |

v2 不允许 `branding.login`。企业介绍、宣传语、指标、业务链、团队、产品、SEO 正文和联系方式属于独立站运营资料，不能在系统配置中复制一份。

## 独立站初始化草稿

`data/company-site.json` 使用 `company-site-seed-v1`，只用于新环境初始化：

```text
company-site seed
├─ enterpriseId                 必须与企业包及运行配置一致
├─ siteKey=primary              隔离单租户固定站点键
├─ applyMode=initialize-only    已有现场数据时拒绝覆盖
├─ initialStatus=draft          导入后必须由运营人员显式发布
├─ site
│  ├─ 企业/品牌/工厂名称
│  ├─ 域名、模板和语言
│  ├─ 主题、联系、社交、商标和 SEO
│  └─ Logo/favicon 素材相对路径
├─ content
│  ├─ 页面、产品及多语言
│  ├─ 方案、案例、证书和下载
│  └─ 证据、知识、SEO、关键词和外部档案
└─ governance                   事实确认状态与非秘密说明
```

Seed 内的内容记录只能缺省状态或标记为 `draft`。它不能直接生成 `published_snapshot`，不能覆盖企业站点运营中尚未发布的草稿，也不能用初始化动作代替审核、发布与回滚。

## 素材约束

- 素材只允许位于企业包 `assets/`，引用使用包根相对 POSIX 路径，例如 `assets/brand/logo.svg`。
- 运行配置需要挂载后的 URL 时使用 `/config/assets/...`；生成器把它映射回企业包素材并检查存在性。
- 生产包存在素材时必须为 `assetStatus=authorized`；候选、来源不明或仅供研究的素材不得批准生产。
- 不在 JSON 中保存 Data URL、大段 Base64、第三方临时地址、对象存储凭据或本机绝对路径。

## 企业包校验和

生成器先按路径排序全部 payload，逐文件记录原始字节数和 SHA-256，再将 Manifest 去掉 `packageSha256`、递归按对象键排序并序列化，计算包级 SHA-256。生成器保留显式 `createdAt`，不会写入当前时间。因此相同元数据和相同文件一定生成相同的 `manifest.json` 和包级哈希。

部署记录应至少绑定：

```text
核心 Git 提交与镜像摘要
+ 数据库发布 Manifest SHA-256
+ 企业包 ID/版本/packageSha256
+ 环境秘密版本引用
+ 数据库恢复点
```

## 生命周期

1. 实施运营台从权威资料建立 `draft`，未知事实保持缺失或 `pending`。
2. 生成器重建文件清单和包级哈希，校验器检查配置、内容、素材、秘密和完整性。
3. `candidate` 只允许进入隔离测试环境。
4. 事实确认、素材授权、测试和审批齐备后，形成新的不可覆盖 `approved` 版本。
5. 部署先验证同一核心/数据库制品，再挂载运行配置并调用受控初始化接口。
6. 独立站初始化为草稿，由企业站点运营显式检查和发布。
7. 回退同时指定旧核心制品、旧企业包和数据库恢复点；不能靠恢复客户源码分支完成。

## 首批三家资料状态

| 企业 | 当前可用输入 | 仍需关闭的边界 |
| --- | --- | --- |
| 伦度机电 | 现有采集工作簿可作为需求追溯起点 | 品牌、域名、公开产品、素材授权、模块、角色、业务链及 P0 业务资料待确认 |
| 君乐缘 | 已有独立站和 V1/V2/V3 材质成果可作为候选 | 法定主体、正式域名、生产使用授权、最终模块/业务链及迁移范围待确认 |
| 经纬网厂 | 已有 SEO/GEO 站点页面和图库候选 | 现有硬编码内容需转换为发布数据；企业事实、域名和素材授权待逐项确认 |

以上输入都不自动等于生产事实。G4.1 只建立生成和校验能力，不创建看似完整的三家生产包；真实候选包与实施运营台输出映射属于后续 G4.2。
