# G3 ProductionAppGrid 阶段退出审计

## 结论

`eiscore-production/src/components/ProductionAppGrid.vue` 的纯策略拆分阶段通过退出审计。页面从 G3 起点的 2,585 行降至 2,077 行，减少 508 行（19.7%）；数据/AI 上下文、单据业务流、行操作/表单和列编辑已进入 4 个无 Vue、Element Plus、实际 Request、浏览器、Storage 或隐式时间依赖的纯模块，共 49 个具名导出。

该结论关闭的是 ProductionAppGrid 当前纯策略子目标，不等于把页面降到普通组件规模。页面仍有 556 行模板、1,124 行组合脚本和 394 行局部样式；配置持久化、AI Bridge、生产业务下推、工单/领料抽屉、Grid 生命周期和视觉区块的后续拆分必须由真实生产数据、权限、跨模块单据和截图基线驱动。G3 转向当前更大的未退出高风险巨页。

## 已退出页面的职责

| 边界 | 迁出职责 |
| --- | --- |
| 数据 | 默认排序、列类型/级联配置、深拷贝、生产统计、AI 数据样本与列投影 |
| 业务流 | 单据/关系类型、链接/审计 Payload、查询编码、链接投影、流程视图与检验/入库/领料出库三类下推计划 |

## 页面保留职责

- 维护 Vue Ref/Reactive/Computed/Watch，以及 Grid、列管理、工单/领料抽屉和业务流对话框状态。
- 通过生产 Request 适配器执行 15 个配置、单据关系、质量检验、工单/领料更新和生成工单请求，保留 Profile、查重、顺序执行、失败降级与刷新时序。
- 向 AI Bridge 推送 Grid 上下文和公式命令，并接收窗口公式事件；随机字段名、单据号和时间由组合层注入。
- 装配选择行、关注等级、三类业务下推、跨质量/仓储平台导航、成功/警告/错误消息和抽屉生命周期。
- 保留 556 行现有模板和 394 行 Scoped CSS，避免无真实生产数据与截图证据的 Grid、列管理、工单/领料抽屉和业务链布局漂移。

这些职责是当前 ProductionAppGrid 的组合、网络和展示边界。继续拆分需要三家企业的真实工单/BOM/领料数据、生产与仓储/质量权限、跨模块下推查重、失败恢复和多分辨率截图证据；只为跨过 2,000 行阈值拆模板、样式或副作用闭包会扩大回归风险。

## 非阻断项

- 页面仍高于 2,000 行极端审查阈值，逐文件与总债务棘轮继续禁止增长；本阶段接受原因是剩余 1,124 行脚本以真实请求、响应式编排和副作用为主。
- 15 个 Request 全部通过既有生产适配器；新增协议不得继续内联，四组专项会阻止已迁出 Payload、流程和编辑规则回流。
- 非法数量字符串会沿用既有 `NaN` 缺料边界；专项已显式锁定，业务若要收紧必须作为独立规则变更处理。
- 生产构建仍报告既有 `vendor-misc` / `vue-runtime` 循环 Chunk 告警，不能与页面业务重构混合处理。
- 当前只验证离线策略和生产构建，未访问数据库、RPC、AI Agent、质量/仓储模块或企业环境。
- 当前验证机为 Node 26.1.0 / npm 11.13.0；发布证据仍要求 Node 20.19.0 / npm 10.8.2。
