# G3 PurchaseAppGrid 阶段退出审计

## 结论

`eiscore-purchase/src/components/PurchaseAppGrid.vue` 的纯策略拆分阶段通过退出审计。页面从 G3 起点的 2,521 行降至 1,970 行，减少 551 行（21.9%），并退出 ≥2,000 行极端页层级；数据/AI 上下文、采购单据业务流、列编辑及行操作/对话框/Realtime 判定已进入 4 个无 Vue、Element Plus、实际 Request、浏览器、Storage 或隐式时间依赖的纯模块，共 55 个具名导出。

该结论关闭的是 PurchaseAppGrid 当前纯策略子目标，不等于把页面降到普通组件规模。页面仍有 405 行模板、1,226 行组合脚本和 336 行局部样式；配置/字段 ACL 持久化、24 个真实 Request、AI Bridge、需求→订单→到货→入库执行链、Realtime/Timer 生命周期和视觉区块的后续拆分必须由真实采购数据、权限、跨模块单据与截图基线驱动。G3 转向当前更大的未退出高风险巨页。

## 页面保留职责

- 维护 Vue Ref/Reactive/Computed/Watch，以及 Grid、列管理和采购业务流对话框状态。
- 通过采购 Request 适配器执行 24 个配置、字段 ACL/标签、供应商、采购需求/订单/到货、单据链路和审计请求，保留 Profile、查重、顺序执行、失败降级与刷新时序。
- 向 AI Bridge 推送 Grid 上下文和公式命令，并接收窗口公式/导入事件；随机字段名、单据号、日期和时间由组合层注入。
- 装配选择行、关注等级、三类采购下推、本地与仓储平台导航、成功/警告/错误消息、Realtime 订阅和防抖 Timer 生命周期。
- 保留 405 行现有模板和 336 行 Scoped CSS，避免无真实采购数据与截图证据的 Grid、列管理和业务链布局漂移。

这些职责是当前 PurchaseAppGrid 的组合、网络和展示边界。继续拆分需要三家企业的真实需求/订单/到货数据、采购与仓储权限、供应商停用、重复下推、部分到货、质检/入库失败恢复和多分辨率截图证据；只为继续降行数拆模板、样式或副作用闭包会扩大回归风险。

## 非阻断项

- 页面仍高于 800 行巨页阈值，逐文件与总债务棘轮继续禁止增长；本阶段接受原因是剩余 1,226 行脚本以真实请求、响应式编排和副作用为主。
- 24 个 Request 全部通过既有采购适配器；新增协议不得继续内联，四组专项会阻止已迁出 Payload、流程、编辑和操作规则回流。
- 工具栏订单/到货状态校验继续延迟到确认执行阶段；专项显式锁定该既有时序，若要提前阻止必须作为独立产品规则变更处理。
- 采购构建仍报告既有 `vendor-misc` / `vue-runtime` 循环 Chunk 告警，不能与页面业务重构混合处理。
- 当前只验证离线策略和采购构建，未访问数据库、RPC、AI Agent、仓储模块或企业环境。
- 当前验证机为 Node 26.1.0 / npm 11.13.0；发布证据仍要求 Node 20.19.0 / npm 10.8.2。
