## 产品化风险

### 架构边界

- 巨型入口和页面混合了传输、状态、业务规则、持久化调用与界面职责。
- 公共 Grid 通过复制传播，修复需要多处同步且容易产生行为差异。
- HTTP、认证、错误处理和浏览器存储访问分散，难以统一安全与兼容策略。

### 多企业配置

- 南牌 Logo、域名和默认服务器仍出现在登录、设置、移动端、Compose 和测试代码中。
- 当前形态容易演变成客户分支，尚未形成“同一制品、不同配置”的产品模型。

### 构建与质量

- CI 已覆盖离线回归和构建，但尚未形成统一 lint、类型/静态分析、组件测试、密钥扫描和迁移校验门禁。
- 多锁文件和依赖漂移增加了环境差异及供应链维护成本。
- 当前仅验证了语法门禁；完整离线回归、前端构建和本地集成测试仍需在保护现有在途改动后形成正式结果。

### 数据与部署

- SQL 目录混合结构脚本、补丁、演示数据和客户数据，缺少唯一迁移顺序与执行账本。
- 生产 Compose 存在可回退到固定默认值的数据库密码和 JWT 密钥。
- 客户域名出现在生产部署配置中，部署模板与企业配置尚未解耦。

验证过程中修复了两个跨环境工程缺陷：

- Windows 与较新 Node.js 组合下，统一 npm 子包运行器可能以 `EINVAL` 失败；现优先通过当前 npm 的 CLI 入口启动子命令，并保留兼容回退及明确错误输出。
- 桌面采集器发布脚本依赖 PowerShell 自动加载 `Get-FileHash`；现改为直接使用 .NET SHA-256 API，并由发布打包回归保护。

本机全局 Node/npm 安装存在运行时错配，因此依赖安装和完整前端构建使用符合仓库 `engines` 约束的隔离 Node 24/npm 11 运行时完成。CI 仍以工作流声明的 Node 20.19.0 为标准环境。
