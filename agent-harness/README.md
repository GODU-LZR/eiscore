# Harness source bundle

Build the shared native ESM runtime and plugin entrypoints without downloading dependencies:

```sh
node scripts/build-yayu-harness-bundle.mjs --output /absolute/empty/harness-bundle --version 1.0.0
node scripts/validate-yayu-harness-artifacts.mjs --harness-root /absolute/empty/harness-bundle --flash-patch /absolute/empty/harness-bundle/dsh-flash-web.patch.yml
```

`harness-artifact-manifest.json` records the source Git revision, whether the adapter sources have uncommitted changes, and SHA-256 of every bundled file. `adapter-provenance.json` identifies the registered JavaScript adapters used as the starting point; the current sources have generic gateway validation and explicit user/session/app checks. These historical source paths identify provenance and are never deployed as a customer directory. The build copies the reviewed source, renderer assets and licenses, and generates two native ESM plugin package entrypoints. It does not consume ignored candidate directories or compile unpublished TypeScript packages.

Run the bundle in the pinned DSH 0.1.2-rc.1 image. The official launcher resolves its installed SDK through `/opt/bridge/node_modules/@deepseek-ai/dsh/package.json` and links the package closure into the writable `$DSH_HOME/profiles/node_modules`. The EISCore adapters import only Node built-ins and bundled relative modules, so no `node_modules` symlink is required inside the read-only bundle. Keep Bridge `DSH_CWD` and Web plugin paths pointed at `/opt/eiscore-harness`.

Web authentication uses the one-time EISCore handoff and an HttpOnly cookie. `EISCORE_AUTH_GATEWAY_URL` must reach the business authentication service; it can differ from `EISCORE_GATEWAY_URL` for the isolated Flash network. Tool session owners persist as hashes of tenant and user, while bearer tokens stay in memory and are checked on each tool request. Browser credentials are required to bind a new DSH session, and an existing session cannot change owner. Each Flash create/prompt waits for both the user binding and the current app registration before forwarding to DSH. The bound app and token are rechecked before a draft tool runs; logging out revokes tool access. The parent Flash Builder continues to poll the draft and refresh its existing preview after a successful draft write.

The Web patches disable the generic shell, filesystem, web and subagent tools. `DSH_PROVIDER` defaults to `deepseek-official`; `DSH_MODEL` defaults to `deepseek-flash`. Set `DEEPSEEK_API_KEY` in the corresponding Web service; DSH resolves it from the inherited process environment. An optional `DEEPSEEK_BASE_URL` selects a compatible endpoint. Existing DSH settings and existing session model selections can override the default, so verify a new session after changing deployment model settings. No credentials file is generated by the bundle build.
