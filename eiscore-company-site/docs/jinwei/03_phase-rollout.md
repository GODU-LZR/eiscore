# 经纬网厂实施分期与验收门槛

## 总原则

先让业务用同一份规格和同一条交接链工作，再接入设备自动采集和复杂计划优化。每一期都要能回滚、可审计，并且不把历史样表直接当成生产事实。

## Phase 0：确认与建模

目标：把调研中的“事实、样表字段、建议和待确认项”签成一份主数据清单。

交付：

- 公司、客户、供应商、机台、工位、仓库/库位和人员角色主数据。
- 产品族、规格字段、单位、允许偏差、检验项目和包装规则。
- 合同、规格版本、交付批次、委外单和包装码编号规则。
- 权限矩阵、审计要求、移动设备和现场网络清单。

验收门槛：业务负责人能逐项标记“确认/不适用/待补资料”，没有把演示数据标成正式数据。

## Phase 1：规格、合同与询盘

目标：公开独立站和内部规格闸门使用同一套字段，减少反复抄写。

范围：

- 独立站规格询盘和幂等提交。
- 客户、合同、合同明细和规格版本。
- 版本锁定、缺项提示、报价前人工审核。
- 销售/计划角色的查看和确认权限。

验收门槛：同一规格从询盘转成合同明细后，字段、单位和版本号可逐项比对；关键字段缺失时不能生成生产任务。

## Phase 2：库存齐套与工序交接

目标：替代“领用、移交、发出、交回”手写记录，先覆盖最小可用扫描链。

范围：

- 原料、半成品、包材批次和库位。
- 领用、移交、接收、委外发出/交回的交接单。
- 合同归属库存、数量差异和异常待办。
- 车间、仓库、计划员和质检的移动/PDA 操作。

验收门槛：扫描一笔交接可反查合同、规格版本、批次、数量、操作者和时间；数量或合同不一致时阻止过站并生成异常。

## Phase 3：生产报工、质量与包装追溯

目标：从原料批次贯通到包装单元，支持分批交付。

范围：

- 拉丝、并线、络筒、整经、有结/无结织网、捻线、成绳、补网、定型、剪断等工序报工。
- 来料、过程、补网、定型和成品检验。
- 条/件换算、净重、唇头/唛头、包装码和成品入库。
- 追溯链、质量放行闸门和分批拣货出库。

验收门槛：给定包装码，系统能在权限范围内反查原料、机台、班次/人员、检验、委外交接和合同归属；未放行的包装单元不能入库或发货。

## Phase 4：设备与计划优化

目标：在人工报工稳定后，再减少重复录入并优化交期。

范围：

- 机台状态、产量和关键参数的 PLC/接口采集。
- 机台规格矩阵、换线损耗、产能日历和瓶颈分析。
- 采购建议、外协负荷、交期预测和异常升级。

验收门槛：自动采集与人工报工可对账；网络中断可离线缓存并补传；任何自动排程建议都能显示依据、人工确认和回滚记录。

## 数据迁移策略

1. 原始 XLS、DOC 和 JPG 永久保存在只读资料区，记录文件哈希和来源路径。
2. 仅将经业务确认的主数据和合同字段导入正式库，历史合同先标记为 `historical`。
3. 旧表中的自由文本拆成结构化字段时保留原始值和转换说明。
4. 迁移前后抽样核对合同数量、单位换算、分批交付和包装规则。
5. 任何批量导入都使用幂等键、导入批次和审计日志，禁止直接覆盖现有记录。

## 上线前必须回答的问题

- 哪些产品和工序先做试点？建议先选一条无结网或有结网路线，覆盖织造、补网、定型和包装。
- 现场是否每个工位都有稳定 Wi-Fi/4G，扫码枪还是 PDA？
- 质检放行由谁最终负责，异常是否需要经营者审批？
- 外协染色的数量损耗、交期和质量争议如何记账？
- 客户唛头、印刷版和包装袋是否需要版本审批？
- 合同归属库存能否在现有财务/仓储系统中同步，还是由经纬模块作为唯一来源？
